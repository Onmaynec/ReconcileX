# Changelog

## 0.4.0 — Security & Data Integrity

### Доступ и сессии
- JWT содержит `ver` и сверяется с серверным `User.token_epoch`, обеспечивая отзыв всех прежних сессий при смене/сбросе пароля и отключении пользователя.
- Добавлены самостоятельная смена пароля и выход со всех устройств, административный сброс пароля, блокировка и восстановление пользователя, отзыв SourceGrant.
- Для администратора добавлены списки пользователей и действующих грантов без хешей паролей. Все изменения аудируются без записи секретов.
- Запрещены отключение собственного администратора и отключение последнего активного admin.

### Финансовая безопасность
- Close/reopen теперь проверяет права контролёра на каждый задействованный источник периода, включая записи, исключения, группы и зафиксированные правила заданий.
- Worker блокирует и перепроверяет enabled, роль submitter и SourceGrant перед финансовым commit. Отозванные разрешения приводят к отказу без частичной записи.
- Конкурентное создание перекрывающихся периодов сериализовано через PostgreSQL advisory lock.

### Проверки
- Добавлены негативные E2E тесты на отзыв JWT, отключение пользователей, изменение паролей, source isolation, запреты на исходные файлы, повторное открытие и конкурентное создание периодов.
- Проверена миграция 0004 при переходе с базы v0.3 и на чистом стенде.

### Ограничения
Production TLS, внешнее управление секретами, полная многопользовательская security-приёмка и off-site DR пока остаются отдельными задачами. Issues #2, #4, #6 не закрываются только на основании отдельных тестов.

## 0.3.0 — Batch Reconciliation & Load Testing

### Производительность
- Для одиночного правила с обязательным совпадением reference и нулевым допуском по сумме добавлен индексированный поиск кандидатов по счёту, валюте, reference, сумме и диапазону дат.
- Убраны отдельные SQL-запросы поиска кандидатов для каждой строки этого сценария. Запись групп 1:1, участников и событий аудита выполняется партиями до 500 групп внутри одной транзакции PostgreSQL.
- Неоднозначные прямые и обратные совпадения остаются исключениями; при больших суммах сохраняется обязательное утверждение другим контролёром. Для нескольких правил или ненулевого допуска используется прежний универсальный алгоритм.

### Инструменты проверки
- Добавлен end-to-end benchmark HTTP preview/commit, повторного импорта, постановки задания, worker, итоговых финансовых инвариантов и закрытия периода.
- В обычном CI запускается небольшой синтетический E2E-сценарий, результат сохраняется как reconcilex-e2e-synthetic.
- Отдельный workflow_dispatch «Full Reconciliation Benchmark» допускает запуск профиля 80000 пар + 20000 дополнительных внутренних строк (всего 180000) и несколько независимых повторов.
- Добавлены проверки 620 однозначных групп, обратной неоднозначности, повторного задания, точных сумм и четырёх глаз для крупных групп.

### Ограничения
- Полный 180000-строчный прогон не считается прошедшим автоматически: он запускается вручную; его измерения нужно оценивать по фактическому отчёту на конкретном SHA.
- Быстрый путь пока применим только к одиночному правилу с reference=true и tolerance_minor=0. Полная промышленная нагрузочная, off-site и security приёмка остаются отдельными задачами.

## 0.2.0 — Reliability & Operations

### Добавлено
- Сервис ежедневного резервирования PostgreSQL 16 и S3-оригиналов с атомарной публикацией.
- SHA-256 манифест, 7 завершённых поколений по умолчанию, проверка свежести копии.
- Команды backup once, verify, restore-check и status. Проверяется архив во временной PostgreSQL БД с точными финансовыми инвариантами.
- Опциональный HTTPS reverse proxy с пользовательскими сертификатами, TRUSTED_HOSTS.
- Инструмент производительности для 80000 внешних и 100000 внутренних записей и отдельного preview 20000 строк. CI публикует JSON-артефакт сокращённого прогона.

### Исправлено
- Экранирование CSV-формул с ведущими пробелами и управляющими символами.
- Обработка повреждённых ZIP/XLSX как 422.
- Заголовок Retry-After для ограниченного входа (429).
- Конфликт повторного исходника, если источник совпадает, а тип/период загрузки отличается.

### Ограничения
Локальный архив не заменяет off-site копии. TLS требует правильных сертификатов, нагрузочный end-to-end прогон автосверки 180000 строк ещё не пройден, полнота production security не подтверждена. Источник статуса — docs/STATUS.md и GitHub Actions по точному SHA.
