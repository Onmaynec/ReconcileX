# Архитектура ReconcileX

Система состоит из HTTP API (FastAPI), отдельного worker, PostgreSQL и локального S3-совместимого объектного сервиса SILO. Банк и платёжные сети не подключаются.

## Поток импорта

Операционист с правом на конкретный DataSource → профиль формата (ImportProfile, version) → предпросмотр (без изменения данных) → commit.

При commit API проверяет SHA-256 исходного файла, уникальность натуральных ключей и корректность каждой строки. Невалидный файл целиком отклоняется: может сохраняться исходник отвергнутого файла и диагностические исключения, но финансовые Record не создаются. Валидный исходник записывается в хранилище, метаданные ImportBatch и исходные Record — в одной транзакции PostgreSQL. Если запись в объектное хранилище не удалась, финансовая транзакция не проводится; при отказе БД после сохранения оригинала возможен невостребованный S3-объект.

## Финансовые сущности

- DataSource: источник, счёт, валюта; SourceGrant: допустимые пользователю источники.
- ImportProfile: карта колонок, кодировка, формат дат и разделитель, версия.
- ImportBatch: SHA-256 и путь к оригиналу, source/period/profile, число строк и сумма.
- Record: внешняя или внутренняя строка, уникальный natural key, ID batch, raw text, нормализованные поля и amount_minor BIGINT.
- MatchRule: версия, приоритет, допуск в minor units, день-окно и проверяемые признаки.
- ReconcileJob: идемпотентный ключ, зафиксированные правила, статус и lease.
- MatchGroup и MatchMember: связанные записи, состояние, автор, согласующий, rule version, explanation. Единственный active member для record обеспечивается частичным уникальным индексом.
- ReconcileIssue, IssueAssignment, ImportRejection: анализ отклонений, ответственный и отдельно сохранённый оригинал непринятого файла.
- Period/PeriodSnapshot: зафиксированный closed report, набор batches/hash/rules и исторические версии snapshot.
- AuditEvent: append-only журнал без UPDATE/DELETE в PostgreSQL; AuthAttempt: ограничитель повторных неудачных логинов.

Все денежные значения — только integer minor units. ISO-валюта берётся из источника; автоматическая конвертация не предусмотрена. События и закрытие хранят UTC timestamp, дата транзакции берётся из формата источника без неявной смены часового пояса.

## Сверка

Worker получает Job через SELECT FOR UPDATE SKIP LOCKED. Из закреплённых версий правил выбираются кандидаты в одном периоде, валюте и счёте. Уникальность проверяется среди всех правил лучшего приоритета, а не только первого совпавшего правила. Неоднозначность → Issue. Однозначная 1:1 группа подтверждается либо остаётся предложением, если сумма превышает порог риска. Утверждение сравнивает expected_version, запрещает self-approval, блокирует исходные записи и опирается на частичный unique index.

Начиная с v0.3.0 один замороженный rule с require_reference=true и tolerance_minor=0 обрабатывается отдельным индексированным путём. Для внутренних и внешних записей в периоде строятся отсортированные по дате индексы по (account, currency, reference, amount_minor); используется симметричная проверка единственности прямого и обратного кандидата. Подтверждённые и предложенные пары сразу исключаются из дальнейшего рассмотрения. Группы, membership, audit events и exceptions записываются пакетами по 500 внутри одной транзакции; авария на любой партии откатывает весь job. Обычный путь для нескольких правил и ненулевого допуска оставлен неизменным.

Для комиссий оператор вручную создаёт n:1 или 1:n до десяти записей на стороне множественности; group delta считается точно из сумм minor units и сравнивается с tolerance_minor конкретной версии правила.

## Закрытие и восстановление

Контролёр не может закрыть период при queued/running jobs или неподтверждённых группах. Закрытие фиксирует историю batches/hash, версий правил и финансовые показатели; повтор отчёта читает snapshot, а не пересчитывает уже изменившиеся правила. Повторное открытие требует причины, а предыдущий PeriodSnapshot остаётся неизменяемым.

При сбое worker незавершённая транзакция откатывается. Задание с истёкшим lease можно повторить; заблокированные и уникальные active membership не допускают второго подтверждения одной Record. Для восстановления из архива нужны и PostgreSQL, и исходные S3-объекты.

## Локальный запуск и ограничения

Docker Compose использует поддерживаемый S3-совместимый сервер SILO с закреплённой версией образа, поскольку старые официальные образы MinIO больше недоступны в обычных Docker Registry. Для внешнего доступа необходимо настроить HTTPS reverse proxy и секреты; текущий стенд локальный. Оставшиеся требования промышленной приёмки перечислены в STATUS.md.
