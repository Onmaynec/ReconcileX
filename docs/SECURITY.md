# Безопасность ReconcileX v0.4.0

## HTTPS-подключение

В базовом Compose API доступен только на 127.0.0.1:8000, а PostgreSQL и SILO не публикуют порты наружу. Не открывайте API напрямую в интернет.

При наличии действительных сертификата и ключа вашего домена:

1. Сохраните fullchain.pem и privkey.pem в локальном каталоге certs/; каталог исключён из Git.
2. Установите в .env переменную TRUSTED_HOSTS с реальным доменом, например finance.example.com. Значение * запрещено.
3. Выполните docker compose -f compose.yaml -f compose.tls.yaml up --build -d.
4. Проверьте цепочку TLS, HTTPS healthcheck, локальную доступность API и firewall.
5. Настройте обновление сертификатов и внешнее безопасное хранилище секретов.

Шаблон находится в ops/nginx.conf. Он использует TLS 1.2/1.3, HSTS, ограничение тела запроса и перезаписывает ненадёжные forwarded-заголовки. Не запускайте proxy без сертификатов. Опциональная конфигурация — не гарантия production security.

## Данные, права и аудит

Пять ролей: operator, controller, admin, analyst, auditor. Исходные строки доступны только разрешённым ролям и SourceGrant. Аналитику доступны сводные отчёты, но не загрузка оригиналов и не сырой экспорт. Попытка получить исходный файл без прав фиксируется отдельным security-событием в audit.

Большие сверки утверждает отдельный контролёр. Запрет самоподтверждения действует даже при изменении роли автора.

Пароли хешируются Argon2id, JWT подписываются серверным секретом (не менее 32 символов). Эндпоинт входа использует PostgreSQL-счётчик неудачных попыток (пять за 60 секунд для username + адрес подключения), после чего отвечает 429 с Retry-After. При обратном прокси приложение видит IP прокси, а не IP конечного пользователя: для публичного доступа необходим дополнительный сетевой rate limiter.

CSV экспорт предотвращает исполнение формул в табличных процессорах, включая формулы с начальными пробелами и управляющими символами. Повреждённые XLSX/ZIP получают 422 вместо необработанной ошибки. HTTP-ответы имеют no-store, nosniff и no-referrer.

## Незавершённые элементы

Нужны production-секрет-менеджер, MFA/SSO по требованиям окружения, реальное сетевое ограничение запросов, негативные E2E тесты всех маршрутов и независимое тестирование аварийных сценариев. Смотрите Issue #4 и STATUS.md.

## Отзыв сессий и управление аккаунтами (v0.4.0)

JWT включает claim `ver` и подписывается как ранее HS256. При каждом запросе сервер загружает текущего пользователя из PostgreSQL, проверяет enabled и точное совпадение `ver` с `users.token_epoch`. Если версия изменилась, запрос возвращает HTTP 401.

- `POST /api/v1/auth/change-password`: `{"current_password":"...","new_password":"..."}`. Требуется текущий пароль; все прежние JWT отзываются.
- `POST /api/v1/admin/users/{id}/reset-password`: `{"new_password":"..."}`. Требуется admin, новый секрет не выводится в audit.
- `POST /api/v1/admin/users/{id}/disable`: admin, блокировка новых запросов и повышение token_epoch.
- `POST /api/v1/admin/users/{id}/enable`: admin; прежние токены остаются недействительными, нужно войти заново.
- `POST /api/v1/admin/grants/revoke`: `{"user_id":"UUID","source_id":"UUID"}`. Требуется admin; операция идемпотентна, audit создаётся при фактическом отзыве.

Нельзя отключить собственную административную учётную запись. При отключении администраторов используется согласованный порядок блокировок и проверка, что останется хотя бы один активный admin.

### Согласованность отзыва при работе worker

Перед финансовой сверкой worker блокирует строку учётной записи и выданные ему SourceGrant до окончания транзакции. Если администратор отозвал разрешение раньше, worker не подтверждает ни одной пары. Если worker уже начал операцию, запрос отзыва ждёт окончания этой транзакции: окончание административного запроса означает, что раньше начатая транзакция уже завершена. Ошибка job фиксируется с состоянием failed. Для снятия блокировки задания в ошибке нужно заново выдать право и явно повторить задачу.

### Периоды и аудит

Оператор и контролёр не имеют глобального права на все финансовые источники: close/reopen проверяет Batch, Record, MatchGroup, ReconcileIssue и rules_snapshot всех заданий в периоде. История закрытий продолжает фильтроваться по SourceGrant. Запрещённые попытки загрузки оригиналов пишутся в отдельный append-only audit.

### Ограничения

Миграция не заменяет управление секретами и TLS. Новые JWT выдаются только после подтверждения нового пароля, а для распределённой авторизации обязателен доступ к PostgreSQL. Внешнее TLS-развёртывание, MFA, центральное хранилище секретов, сетевой rate limiter и полный формальный RBAC-аудит остаются за рамками этой версии.

### Самостоятельный выход и инспекция прав

`POST /api/v1/auth/logout-all` инвалидирует все уже выпущенные JWT данного аккаунта; после этого требуется повторный логин.

`GET /api/v1/admin/users?limit=100&offset=0` возвращает только id, username, роль и статус enabled. Хеши паролей и детали сессий не раскрываются. `GET /api/v1/admin/grants?user_id=UUID` показывает список действующих SourceGrant конкретного пользователя. Для обоих методов обязательна роль admin.
