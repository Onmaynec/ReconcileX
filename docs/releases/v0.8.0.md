# ReconcileX v0.8.0 — Security & Deployment Hardening

Версия усиливает границу доверия между клиентом, TLS reverse proxy и API. Главная задача — не позволить клиенту подменять свой IP через forwarded headers и обходить ограничения входа.

### Изменения
- trusted_client_ip() использует TCP peer по умолчанию и принимает X-Real-IP только от явно доверенного proxy CIDR. Неверный forwarded IP и spoofing от прямого клиента игнорируются; некорректная конфигурация CIDR отклоняется.
- Login throttle приложения теперь использует username + доверенный IP клиента.
- Nginx ограничивает /api/v1/auth/token на уровне reverse proxy: 5 запросов/минуту, burst 2, HTTP 429.
- TLS proxy закреплён за статическим адресом Compose; subnet, proxy IP и trusted CIDR вынесены в .env.example.
- Nginx перезаписывает клиентские forwarding headers, добавляет HSTS, X-Frame-Options и Permissions-Policy, скрывает server version.
- CI создаёт временный сертификат, запускает TLS proxy, проверяет HTTPS health, защитные заголовки и rate limit при поддельном X-Real-IP.
- Добавлены тесты доверенного и недоверенного proxy, API auth contract и admin-only inspection endpoints.

### Совместимость
Миграций PostgreSQL нет. Для локального Compose дополнительные шаги не требуются. Для TLS Compose используйте согласованные BACKEND_SUBNET, TLS_PROXY_IP, TRUSTED_PROXY_CIDRS и TRUSTED_HOSTS. Изменение subnet/IP требует пересоздания Docker network.

### Ограничения
Issue #4 остаётся открытым: MFA/SSO, внешний secret manager, полный RBAC acceptance по всем бизнес-операциям, независимый security review и проверка реального сертификата/домена не выполнены этой версией. CI использует временный self-signed сертификат и не подтверждает production trust chain. Issue #2 (полная нагрузочная приёмка) и Issue #6 (независимое DR испытание) также открыты.
