# ReconcileX v0.7.0 — Multi-Rule Engine

Версия расширяет индексированную сверку на все автоматически обрабатываемые правила, устраняя SQL-поиск кандидатов на каждую запись в прежнем многоправильном алгоритме.

### Реализовано
- Общий `_reconcile_indexed_rules` для одного и нескольких правил, с и без обязательного reference, с нулевым и ненулевым допуском.
- Четыре вида индекса по дате и сумме создаются только для реально необходимых правил. Подгружаются минимальные финансовые поля, без исходного `raw_text` и JSON.
- Проверяется приоритет правил. Несколько кандидатов одного уровня дают `ambiguous`, совпадение одной записи по разным правилам не считается неоднозначностью. Обратный поиск обязан однозначно подтвердить пару.
- Точный `delta_minor`, лимиты дат, счёта и валюты, high-risk proposal и независимое approval сохраняются.
- Массовые группы, участники, разрешения исключений и аудит остаются атомарной PostgreSQL-транзакцией с пакетной вставкой по 500.

### Проверки и бенчмарк
- Регрессии на 621 пар: 500 точных, 120 с допуском и 1 по широкому правилу, проверка выбранного приоритета, сумм, аудита и идемпотентности.
- Негативные проверки forward/reverse ambiguity между равноприоритетными правилами, выхода за допуск/окно дат и high-risk.
- E2E-бенчмарк получил `--rules-mode priority-fallback` для двух правил. CI выполняет небольшой HTTP-import → worker → close и сохраняет JSON-артефакт. Ручной workflow поддерживает тот же режим.

### Совместимость и ограничения
Миграций базы нет. Права доступа, формат файлов и настройки Compose не изменены. Полный прогон 180000 строк, набор шести форматов, промышленная параллельная нагрузка, p50/p95 на выбранном оборудовании не подтверждены; Issue #2 остаётся открытым. Независимое DR (#6) и полный security acceptance (#4) также открыты. Реальные результаты бенчмарка проверяйте в GitHub Actions по SHA релиза.
