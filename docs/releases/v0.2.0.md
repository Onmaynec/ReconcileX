# ReconcileX v0.2.0 — Reliability & Operations

Обновление серверной системы финансовой сверки PV-FIN-03.

### Новые возможности

- Автоматическое резервирование PostgreSQL и S3-оригиналов: первый архив после запуска сервиса и последующие по расписанию UTC.
- Проверка SHA-256 дампа и каждого оригинального файла, атомарное опубликование архива, ротация завершённых поколений. По умолчанию хранятся 7 поколений.
- Проверка восстановления в отдельную временную PostgreSQL-базу. Сверяются количество и сумма записей по каждому импортному пакету, связанные оригиналы, SHA-256 исторических закрытий.
- Состояние backup-контейнера сигнализирует при отсутствии свежего архива старше 36 часов.
- Опциональный TLS reverse proxy с пользовательскими сертификатами и TrustedHost-проверкой.
- Инструмент нагрузочных измерений с профилем 80 000 внешних и 100 000 внутренних строк, p50/p95, CPU/RAM, отдельным preview 20 000 строк и выгрузкой JSON.

### Исправления безопасности и обработки файлов

- Формулы с ведущими пробелами, табами и переводами строк нейтрализуются в CSV-экспорте.
- Повреждённые XLSX/ZIP получают HTTP 422 вместо необработанного исключения.
- При HTTP 429 выдаётся Retry-After: 60.
- Повторный файл с иным типом операции или периодом не принимается как обычный идемпотентный повтор.
- Заголовки ответа настроены на no-store, nosniff и no-referrer.

### Проверки

CI запускает PostgreSQL 16, SILO, API, worker и backup, интеграционные проверки, повторную загрузку исходников, восстановление резервной копии и сокращённый нагрузочный протокол. Отчёт CI доступен в GitHub Actions, результаты синтетического benchmark сохраняются артефактом.

### Ограничения

Это инженерный backend, а не полностью принятая промышленная финансовая платформа. Для эксплуатации за пределами локальной сети нужны корректные TLS-сертификаты, отдельные секреты и учётные записи, внешние зашифрованные резервные копии. Полный сквозной тест автоматической сверки 180 000 строк и production security audit остаются открытыми в Issues #2 и #4.
