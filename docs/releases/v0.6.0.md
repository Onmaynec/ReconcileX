# ReconcileX v0.6.0 — Reconciliation Performance

Обновление движка сопоставления финансовых записей, измеримости E2E и сохранения точных сумм при ненулевом допуске.

### Что изменилось
- Для одиночного reference-aware правила включён индексированный путь 1:1 с ненулевым допуском суммы, ранее доступный только для точного совпадения.
- Бинарный поиск по диапазону суммы в minor units и проверка окна дат снижают количество повторных SQL-запросов к кандидатам.
- Сохранены обратная проверка однозначности и запрет угадывания при нескольких возможных парах, RBAC и независимое согласование high-risk.
- Group, explanation и audit содержат действительное значение `delta_minor`; риск рассчитывается по максимальной абсолютной сумме двух сторон.
- Сохранены пакетная запись по 500 строк, атомарность транзакции, идемпотентность и отсутствие активного дублирования.

### Тестирование
- Регрессии 620 1:1 пар с разницей `−2` и `+3` в minor units, включая несколько транзакционных батчей.
- Отрицательные проверки forward/reverse ambiguity, превышения tolerance, выхода за day_window, повторов и четырёх глаз.
- Отдельный E2E CI-замер с 250 парами, допуском 5 minor units и финансовой дельтой 3; параллельно остаётся exact E2E.
- В бенчмарк и ручной workflow «Full Reconciliation Benchmark» добавлены параметры `tolerance_minor` и `drift_minor` и проверка `approved_delta_minor`.

### Совместимость и ограничения
Миграции базы не нужны. Правила без обязательного reference и источники с несколькими правилами продолжат работать по прежнему универсальному алгоритму. Полный проверенный 180000-строчный прогон на отдельном оборудовании и многопользовательская нагрузочная приёмка **не выполнены** — Issue #2 остаётся открытым. Внешний security acceptance #4 и DR #6 также открыты.

Релиз публикуется из main только после успешного Backend CI, фактические результаты смотрите в Actions по точному SHA.
