# ReconcileX v0.3.0 — Batch Reconciliation & Load Testing

В этом выпуске ускорена массовая автоматическая сверка 1:1 при одиночном строгом правиле. Добавлен проверяемый end-to-end сценарий вместо оценки только парсинга.

## Что изменилось
- Индексирование кандидатов по счёту, валюте, reference, точной сумме и дате — без SQL-поиска на каждую внешнюю запись для одиночного reference-aware правила с tolerance_minor=0.
- Запись match groups, members, audit events и исключений пачками до 500 объектов в одной атомарной транзакции.
- Запрет произвольной пары при нескольких прямых или обратных кандидатах сохранён. Крупные суммы требуют отдельного утверждения контролёром.
- Новый сценарий scripts/e2e_benchmark.py: HTTP preview/commit, повторные импорты, worker, финансовые проверки, закрытие периода, JSON-отчёт. Поддерживаются повторные прогоны с p50/p95.
- Дополнительный ручной workflow Full Reconciliation Benchmark для 80000 пар и 20000 дополнительных внутренних операций; сокращённый E2E-прогон выполняется в обычном CI.
- Новые регрессии на 620 пар, неоднозначность в обратном направлении и high-risk approval.

## Проверки и статус
Версия публикуется только после успешной проверки Backend CI в main. Для фиксации фактических цифр полного нагрузочного запуска откройте Actions и запустите Full Reconciliation Benchmark. Результаты должны оцениваться по JSON-артефакту конкретной ревизии.

## Ограничения
Быстрый путь не распространяется на несколько правил и ненулевой tolerance; полный 180000-строчный запуск ещё не является доказанным по одному лишь факту добавления workflow. Issue #2 остаётся открытым до полноценной нагрузочной приёмки. Production security (#4) и off-site disaster recovery (#6) также не закрыты.
