# ReconcileX v0.5.0 — Off-site Recovery

### Добавлено
- Опциональная репликация законченных архивов PostgreSQL + SILO в независимое HTTPS S3-хранилище с отдельными credentials.
- Принудительное SSE-AES256/SSE-KMS; HMAC-SHA256 подпись manifest.json отдельным секретом и проверка всех remote объектов после передачи по SHA-256.
- Публикация manifest.json только последней условной S3-записью, защита от неполных снимков и повторов с повреждёнными объектами.
- Локальная ротация не выполняется при ошибке внешней репликации, чтобы не уничтожить последнюю доступную копию.
- Команды `offsite-sync`, `offsite-verify`, `offsite-drill`; контроль внешнего снимка командой `status` и необязательный HTTPS webhook для событий failed/stale.
- Файл `compose.offsite.yaml` для осознанного включения механизма и подробная инструкция по retention, Object Lock, ключам и восстановлению.
- Негативные тесты шифрования, HMAC, повреждённых файлов, частичных uploads и восстановления после потери локального снимка. CI проверяет Compose-override и тестирует транспорт на имитированном S3.

### Совместимость
Поведение локального Compose без `compose.offsite.yaml` не меняется. Миграции PostgreSQL не требуются. При включённой репликации требуется подготовленный внешний bucket с HTTPS, отдельные ключи и отдельный HMAC secret. Копии содержат конфиденциальные данные: запрещена выгрузка в публичные CI-артефакты.

### Ограничения
Сценарий `offsite-drill` восстанавливает только во временную PostgreSQL-БД, не переключает production и не заполняет новый объектный bucket. Реальное внешнее хранилище, Object Lock, восстановление на независимой машине, измеренные RPO/RTO ещё требуют эксплуатационных испытаний. Issue #6 остаётся открытым; #2 и #4 также не закрыты.

Публикация версии производится только после успешного Backend CI основной ветки. Смотрите историю GitHub Actions для конкретного SHA.
