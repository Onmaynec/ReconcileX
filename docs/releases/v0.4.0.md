# ReconcileX v0.4.0 — Security & Data Integrity

Релиз посвящён отзыву доступа, усилению административного управления и конкурентной целостности финансовых операций.

### Новые возможности
- Версионирование JWT-сессий через `users.token_epoch` и claim `ver`.
- Смена собственного пароля с проверкой предыдущего; административный reset без сохранения секрета в audit.
- Отключение/включение пользователей и идемпотентный отзыв доступа к конкретным источникам.
- Прямой запрет отключения самого себя в роли admin или последнего активного администратора.
- Повторная проверка и блокировка учётной записи/грантов worker на время финансовой транзакции.

### Исправления безопасности
- Закрытие и повторное открытие периода больше не обходят ограничения SourceGrant для контролёра. Проверяются все фактически задействованные источники.
- Параллельные запросы на создание пересекающихся периодов сериализованы.
- Миграция Alembic `0004_session_epoch` поддерживает как существующую базу v0.3, так и установку с нуля.

### Тесты
Новые негативные интеграционные проверки на JWT, роли, source isolation, отмену прав фонового задания и конкурентные операции. GitHub Release публикуется только после успешного CI основной ветки. Для промышленной эксплуатации дополнительно нужны собственный TLS, хранение секретов, полная RBAC-приёмка и off-site резервирование.

### Совместимость
Токены, выпущенные предыдущими версиями без `ver`, перестанут проходить проверку: пользователям необходимо заново авторизоваться. API финансового импорта, правил и сверки сохранён.
