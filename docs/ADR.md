# ADR — решения ReconcileX

## 001 — Финансовые суммы

Деньги — BIGINT в минимальных единицах валюты. Входные значения проверяются Decimal; округление и float-арифметика запрещены. Комиссия записывается отдельным отрицательным значением.

## 002 — Конкурентное согласование

MatchGroup и Record блокируются транзакцией PostgreSQL. Частичный уникальный индекс match_members(record_id) WHERE active запрещает участие одной строки в двух подтверждённых группах. Номер версии исключает устаревшее согласование.

## 003 — Восстановление worker

Job хранит Idempotency-Key, неизменяемый набор версий правил и lease. Worker захватывает задания SKIP LOCKED. Финансовые изменения одного задания и завершение задания проводятся в одной транзакции. При отказе процесса незакоммиченная транзакция откатывается.

## 004 — Сохранность оригиналов

Оригинал файла загружается в S3-совместимый bucket по SHA-256. PostgreSQL хранит hash, origin source, batch, raw_text и нормализованные значения. Неудачный commit БД может оставить неиспользуемый объект; данные не проводятся. Это нужно отслеживать отдельной процедурой.

## 005 — Закрытие периода

Закрытие фиксирует batch IDs, file hashes, rule versions, отчёт и SHA-256 snapshot. Нельзя изменять закрытые финансовые цифры после изменения правил. Повторное открытие возможно только с причиной и аудитом.

## 006 — Доступ

JWT+RBAC+SourceGrant. Сервер проверяет права на списки, исходные записи, выгрузки и файлы, а не полагается на клиентское скрытие кнопок. Администратор создаёт профили, права и правила, но не утверждает финансовые решения.
